- Added renewable programmatic liveness: a pure reducer in the new `liveness.ts` evaluates three independent monitor clocks each 100 ms supervisor tick with fixed precedence. Valid RPC health (every framing- and correlation-valid record), accepted activity (lifecycle transitions, nonempty deltas, novel tool updates, retry/compaction; empty deltas, unchanged queues, and identical accumulated tool updates excluded), and novel structural progress (prompt acceptance, authoritative `message_end`, `turn_end`, `tool_execution_end`, final `agent_end`, `agent_settled`). Defaults: five-minute activity warning, ten-minute activity-idle stop, 30-minute progress warning, and a renewable 45-minute maximum gap between novel structural checkpoints. Checkpoint novelty uses one random per-attempt in-memory HMAC key over a bounded 64-entry digest index; keys, digests, and raw inputs are never persisted, rendered, or returned and are dropped when the attempt ends. Exact repeated checkpoints increment bounded duplicate counters without renewing the lease.

Report recovery keeps exactly one same-session round; the work-budget condition is removed, round 2 restarts the RPC and activity clocks under a distinct five-minute idle lease, and a silent recovery round stops as `report_recovery_idle`. Fallback needs only positive cleanup proof; every operational failure state including any stall remains eligible regardless of elapsed time, and restart-after-work, terminal states, output cap, interruption, cleanup timing, process-group proof, routing, roles, concurrency, resources, and prompt-efficiency behavior are unchanged. Failure diagnostics move to schema 6 (new bounded liveness ages and counters; no work budgets); schema 3-5 files are not migrated.

## 2026-08-27 — Remediate confirmed PR #13 review findings: public/runtime resource bounds, Exa Contents identity, Firecrawl target status, and complete persisted-diagnostic bounds

- `fetch_contents` now enforces explicit public and runtime resource bounds: the schema declares `uris.maxItems: 25` and `maxCharacters.maximum: 50000`, and runtime validation rejects more than 25 raw URLs (`uris must contain at most 25 URLs`) and `maxCharacters` above 50000 before any config load, cache read, provider call, or cache write. Input validation is split into the config-independent `validateFetchContentsInput` (raw shape, URI cardinality/strings/URL normalization, `maxCharacters`, explicit `maxAgeHours`) and a post-load `resolveFetchContentsInput` that resolves the absent `maxAgeHours` from `contents.defaultMaxAgeHours` (`parseFetchContentsInput` keeps composing both), so an invalid input always wins over a failing config loader in both `executeFetchContents` and direct `fetchContentsEntries` (loader never called, `invalid_input` preflight record with safe metadata and no attempts), while a valid input with a failing loader stays `config_load_failure`; a deterministic `setConfigLoaderForTests` seam proves loader call counts and categories without touching the real config file or live HOME. `executeFetchContents` classifies cap violations as preflight `invalid_input` records carrying only safe metadata (the URL count and any valid numeric limit fields supplied) with an empty attempt list. Shared `MAX_FETCH_CONTENT_URLS`/`MAX_CONTENT_CHARACTERS` constants live in the new dependency-neutral `src/limits.ts` shared by schemas and contents so the public contract and runtime validation cannot drift. Configured `contents.concurrency` is honored only for integers 1..10 (default 3 retained; other values silently fall back to 3), and the scrape fan-out hard-caps at 10 concurrent workers even for injected configurations.
- Exa Contents result attribution now follows a strict identity policy: result identity precedence is the normalized `url`, then `uri`, then a URL-like `id`, per-URL statuses are matched through the same normalized identity, and positional attribution survives only as legacy tolerance when exactly one URL was requested and the single returned result carries no identity at all. In unordered or partial multi-URL batches, an id-only result maps only to its own requested URL and unidentified results are never cross-assigned, including the single-unidentified-result case where the old positional fallback wrongly satisfied every requested URL (now a generic empty failure per URL with nothing cached); unmatched URLs stay empty, non-cacheable failures and are never written under another URL's cache key.
- Firecrawl Scrape usability now also requires the fetched target page's own status (`metadata.statusCode`) to be absent or below 400: a provider 2xx wrapping a 404/500 error page is recorded as `unusable_response`, its error-page Markdown is never returned or cached, and the URL moves to the Exa Contents fallback (generic failure when Exa fails too). Absent, 2xx, and 3xx target statuses remain usable.
- Persisted diagnostics now bound every provider-controlled normalized value through explicit bounded storage copies instead of generic attempt/result spreads: grounding answers at 20 000 characters with finish/block/model/ID/domain/title/URL/support-text/query strings bounded at 500, at most 25 sources/supports/web-queries and 25 chunk indices per support with total/omitted counters, and arbitrary `usageMetadata` kept in ordinary shape only when its redacted serialized form fits 20 000 characters (otherwise an explicit `{ diagnosticPreview, diagnosticPreviewTruncated }` wrapper; no unbounded object survives); code-search Exa responses at 20 000 characters, at most 25 Firecrawl artifacts with 25 passages each plus counters, all non-response fields at 500, and arbitrary coverage/cost values serially bounded to 500 through the same small-shape-or-preview rule. Raw request URLs of `web_search`/`web_code_search` attempts now use the same 500-character prefix-plus-digest URL bound as fetch records, main-record queries and preflight query metadata are bounded at 2 000 with redaction before truncation, fetch result status labels are redacted/stripped/bounded at 500 in storage with `fetch_contents` tool details reusing those redacted stored statuses and every model-visible status copy likewise stripped and bounded, and the top-level `web_search` normalized field derives from the same bounded selected attempt. Arbitrary metadata hardening: the recursive secret redaction and `JSON.stringify` of arbitrary `usageMetadata`/coverage/cost values now run inside the bounded copy's catch boundary, so a deeply nested JSON-parsed value or a cyclic injected value becomes the constant omission wrapper instead of throwing out of record construction and masking a usable tool outcome. Model-visible `fetch_contents` URL copies (tool output text, tool details, and the TUI fetched-URL list) now reuse the stored redacted 500-character bounded URL copies while provider calls and cache identity keep the full normalized URL, so no returned or rendered fetch URL copy can exceed the bound or carry a secret; the renderer reads only the bounded details copies.
