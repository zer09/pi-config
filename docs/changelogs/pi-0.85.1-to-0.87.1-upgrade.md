## Restart boundary, choices, and rollback

A running parent can retain modules loaded before an on-disk upgrade, so the acceptance matrix used fresh processes. The P0 projection repair passed its tests and independent review. The two rollback snapshots protect old package files but do not prove that opening a target-written session in 0.85.1 preserves context-edit omissions. Keep original sessions isolated; do not test semantic rollback against them.

The operator chose not to add a downgrade test. If a future rollback is exercised, isolate it in a disposable worktree and use disposable sessions only; a worktree does not make Pi 0.87.1-written originals safe under 0.85.1. The cache-warming recommendation is `off` for the parent and its children during this migration. Do not enable `streaming` or `idle` without an explicit cost/privacy decision and account-isolation tests. Browser Harness remains at 0.10.2; adding a daemon runtime dependency or a new package patch needs a separate decision.

For a Blackhole-only rollback under Pi 0.87.1, first stop new Pi processes and package workers and confirm no active session is writing. Restore the exact patched 0.5.8 package directory, `agent/npm/package.json`, `agent/npm/package-lock.json`, `agent/npm/node_modules/.package-lock.json`, `agent/settings.json`, and `agent/pi-blackhole/pi-blackhole-config.json` from `/home/gc/.pi-upgrade-rollback-blackhole-0.5.9-lZNZJE`, checking paths and package versions before restarting. Do not replace unrelated package directories or session data. For a full Pi rollback, stop all writers, verify the older snapshot's `SHA256SUMS`, then restore its matching extension tree, wrapper, and settings without replacing unrelated current data. Use the actual Bun installation mechanism to pin the core to 0.85.1, check its manifest and fresh CLI, and restore the matching four core package directories from the snapshot only with the process quiescent. The snapshot did not include Bun's global manifest/lock; compare those files before and after and do not claim byte-exact global rollback. Never open target-written original sessions under 0.85.1 without an isolation/export plan.

Fresh-process activation, minimal real-provider, delegated-path, Browser Harness JSON-contract, and interactive visual checks also pass. The Pi 0.87.1 upgrade is accepted for normal daily use. If rollback needs an exercise, use a disposable worktree with isolated sessions, not a downgrade test against original sessions.
